# Failed Path Record

> Note: This record documents a failure of an approach, not a person.

## Topic

Tag-triggered npm publication for ORP 0.4.37

## Summary

The `v0.4.37` workflow passed its complete test and package validation stages,
then failed before registry publication. The run exposed both a stale GitHub
Actions npm credential and a non-deterministic package boundary after Python
tests generated bytecode in the checkout.

## What was attempted

- Merged GitHub pull request 6 into `main`.
- Tagged merged commit `2c205758ee16bcd2ecdf0aea353a21bd8db781ce`
  as `v0.4.37`.
- Ran GitHub Actions workflow run `32669051310`.

## Why it failed

- The `NPM_TOKEN` repository secret dated 2026-03-06 was rejected at publish
  time with npm `E404`, while the registry still listed `0.4.36` as latest.
- Tests generated six `.pyc` files under package-allowlisted directories. The
  workflow's pack step therefore computed 210 files and npm SHA-1
  `3f40aca3e65489b88e2926285fd545086e2fe5ca`, instead of the clean candidate's
  204 files.

## Evidence (canonical artifacts)

- GitHub Actions run: `https://github.com/SproutSeeds/orp/actions/runs/32669051310`
- `results/verification/orp-0.4.37-release.md`
- `results/verification/orp-0.4.38-publish-recovery.md`

## What this rules out

Rerunning the unchanged `v0.4.37` workflow or force-moving its public tag.

## What might still work (next hook)

Publish an immutable `v0.4.38` recovery release that explicitly excludes
generated bytecode, validates the computed npm manifest, and uses the newer
approved Keychain credential after securely rotating the repository secret.
